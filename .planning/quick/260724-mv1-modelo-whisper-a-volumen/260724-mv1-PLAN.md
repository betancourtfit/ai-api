<objective>
Move the 466 MB `ggml-small.bin` whisper model out of the Docker image and into a runtime volume at
`/models`, provisioned by the entrypoint with a sha256-verified download when it is missing.
Parametrise the model path/URL/checksum so CI can exercise the whole mechanism with the 77 MB
`ggml-tiny` model instead.

Purpose: the GHA layer cache is at 2.15 GB after three builds, carrying **four** 426 MB copies of the
model layer against a 10 GB LRU ceiling — it is on track to evict the expensive whisper.cpp compile
layer and send build times back to ~239s intermittently. It also makes every image pull on the mini PC
~1 GB, which is what would make the next step (deploy-image + fast rollback) expensive.

Output: a `~350 MB` image, a self-healing model volume, and CI proof of all three boot paths
(cold download, warm cache hit, degraded when provisioning fails).
</objective>

<design_decisions>
Locked by the developer — implement exactly, do not offer alternatives:

- **D-01** The entrypoint downloads the model into the volume when it is missing, with sha256
  verification. Auto-repairing, no manual step.
- **D-02** The CI smoke uses `ggml-tiny` (77 MB) in a temporary volume, not production's
  `ggml-small`, and still performs a real transcription.

Decided here (rationale recorded so the executor does not relitigate them):

- **D-03 Volume path is `/models`, not `/app/whisper-models`.** Mounting a volume over a subdirectory
  of the application directory shadows tracked files (`sample.wav`) under a bind mount and mixes app
  code with mutable data. `/models` is a dedicated mount point and matches the path the builder stage
  already used.
- **D-04 Provisioning runs in a background subshell; the Bun proxy execs immediately.** A synchronous
  466 MB download in front of PID 1 means an EasyPanel healthcheck can kill the container mid-download
  and crash-loop it forever. It also contradicts the standing Phase-6 rule "Bun boot path never blocks
  on sidecar health". Chat must keep working while the model downloads.
- **D-05 Provisioning failure is non-fatal: boot degraded, do not exit.** Chat proxying is the primary
  function; whisper is secondary. Killing the container when HuggingFace is unreachable would take
  chat down too. The degradation is observable (`/ready` → `whisperAvailable:false`, plus a log
  marker) and CI asserts it.
- **D-06 Download to a unique `mktemp` file, verify, then atomically `mv` onto the final path.** This
  is what makes "a half-downloaded file that looks valid next boot" structurally impossible, and it
  makes two containers booting on the same volume safe: `rename(2)` is atomic, both candidates are
  byte-identical and verified, an already-open reader keeps its inode. Concurrent cold boots may each
  download once — accepted, self-limiting, no locking.
- **D-07 Verify the checksum of an already-present model on every boot, not just after downloading.**
  ~1-3s for 466 MB, negligible next to model load time, and it self-heals a file corrupted or
  truncated by any mechanism (including one predating this script).
- **D-08 Provisioning lives in its own `ensure-model.sh`, not inline in `start.sh`.** The logic is new
  and non-trivial, the local Docker daemon is off, and a separate script is directly executable on the
  dev machine — so Task 1 can verify all five paths for real before CI ever sees them. It must
  therefore be portable enough to run on macOS (`sha256sum` OR `shasum -a 256`, bash 3.2 syntax).
- **D-09 CI exercises the real download path rather than pre-seeding the volume.** Pre-seeding is
  faster and more deterministic but leaves the new, non-trivial download code executing for the first
  time ever on the production mini PC — precisely the hole quick task 260724-shs just closed for the
  container itself. A 77 MB HF fetch costs a few seconds on a runner. CI then *also* covers the warm
  and degraded paths with two extra short-lived containers, because the warm path is the one that runs
  on every production boot and the degraded path is the new failure mode this change introduces.
- **D-10 `curl` + `ca-certificates` are added to the final image.** Mild attack-surface increase,
  accepted: the image already ships bash, bun and ffmpeg, this is a single-user personal deployment,
  and it is what makes self-healing provisioning possible without embedding a TS downloader in a shell
  string.
</design_decisions>

  <files>ensure-model.sh, start.sh</files>
  <action>
Create `ensure-model.sh` at the repo root, `#!/usr/bin/env bash`, `set -eu`, mode 0755. It is a
standalone command (not sourced) whose entire contract is: on exit 0 the file at
`$WHISPER_MODEL_PATH` exists and — when a checksum was supplied — matches it; on exit 1 the model is
unavailable and nothing partial has been left behind. It must run unmodified on both Debian (the
image) and macOS (the dev machine) — see D-08.

Inputs, read from the environment, no defaults applied here (start.sh owns the defaults):
`WHISPER_MODEL_PATH`, `WHISPER_MODEL_URL`, `WHISPER_MODEL_SHA256`.

Log markers — these exact ASCII strings are the CI contract, do not reword them, do not use em
dashes or any non-ASCII character in them. Informational markers go to stdout, failure markers to
stderr; `docker logs` captures both:
- `whisper-model: cache hit at <path>`
- `whisper-model: cache hit at <path> (unverified: WHISPER_MODEL_SHA256 not set)`
- `whisper-model: downloading from <url>`
- `whisper-model: install ok at <path>`
- `whisper-model: checksum mismatch on cached file, discarding`
- `whisper-model: unavailable: <reason>`

Portability shim: define a `sha256_of <file>` helper that prefers `sha256sum` and falls back to
`shasum -a 256`, in both cases emitting only the lowercase hex digest (cut the first whitespace
field). If neither binary exists, that is an `unavailable:` reason.

Control flow, in order:
1. `WHISPER_MODEL_PATH` empty → `unavailable: WHISPER_MODEL_PATH is empty`, exit 1.
2. Normalise the expected digest to lowercase with `tr 'A-Z' 'a-z'` (bash 3.2 — do not use `${v,,}`).
   If it is non-empty but does not match exactly 64 hex characters →
   `unavailable: WHISPER_MODEL_SHA256 is not a 64-character hex digest`, exit 1. A typo'd checksum
   must be a loud config error, not a silent re-download loop.
3. `mkdir -p` the dirname of the path; on failure → `unavailable: cannot create <dir>`, exit 1
   (covers a read-only or unmounted volume).
4. If the file exists: with no expected digest, emit the `(unverified: ...)` cache-hit marker and
   exit 0 (an operator who mounted their own model is allowed through). With a digest that matches,
   emit `cache hit at` and exit 0. With a digest that does **not** match, emit
   `checksum mismatch on cached file, discarding`, `rm -f` the file — so a failed re-download leaves
   nothing rather than a known-bad file — and fall through to the download.
5. Before downloading, refuse to fetch anything unverifiable or unencrypted: empty
   `WHISPER_MODEL_URL` → `unavailable: WHISPER_MODEL_URL is empty`; a URL not starting with
   `https://` → `unavailable: WHISPER_MODEL_URL must be https`; empty `WHISPER_MODEL_SHA256` →
   `unavailable: refusing to download without WHISPER_MODEL_SHA256`. Each exits 1.
6. Sweep stale temporaries left by a hard kill (SIGKILL bypasses traps) so they cannot fill the
   volume: `find <dir> -maxdepth 1 -name '.model.*' -mmin +60 -delete 2>/dev/null || true`.
   `-mmin` is portable across GNU and BSD find.
7. `tmp="$(mktemp "<dir>/.model.XXXXXX")"` — `mktemp` retries on collision via `O_EXCL`, so this is
   safe even when two containers share the volume. Immediately install `trap 'rm -f "$tmp"' EXIT` so
   every failure path cleans up without repeating the `rm`.
8. Emit `downloading from <url>`, then
   `curl -fsSL --retry 3 --retry-delay 2 --retry-connrefused --connect-timeout 20 --max-time 1800 -o "$tmp" "$url"`.
   Deliberately **no** `--retry-all-errors`: a 404 (stale/typo'd URL) must fail fast rather than burn
   three retries; `--retry-connrefused` still covers a flaky CDN. On non-zero exit →
   `unavailable: download failed (curl exit N)`, exit 1.
9. Digest the temp file. On mismatch → `unavailable: checksum mismatch (expected <first 12 chars>..., got <first 12 chars>...)`,
   exit 1. Both values are public constants, so logging prefixes is safe and is the only way to debug
   upstream drift.
10. `mv -f "$tmp" "$path"` — same directory, therefore the same filesystem, therefore an atomic
    rename (D-06). On failure → `unavailable: install failed`, exit 1. On success emit
    `install ok at <path>` and exit 0.

Then rewrite `start.sh` (keep `#!/usr/bin/env bash`, change `set -e` to `set -eu` so a typo'd
variable can never expand to an empty `--model ""`):
- Export the three variables with `:-` fallbacks that are byte-identical to the Dockerfile `ENV`
  defaults added in Task 2: path `/models/ggml-small.bin`, url
  `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin`, sha256
  `1be3a9b2063867b937e64e2ec7483364a79917e157fa98c5d94b5c1fffea987b`. The duplication is intentional:
  the Dockerfile `ENV` is what an operator sees in `docker inspect`, the `:-` fallback is what keeps a
  bare `./start.sh` working outside Docker.
- Replace the current foreground `whisper-server ... &` line with a single background subshell that
  runs `"$(dirname "$0")/ensure-model.sh"` as an `if` condition and, on success,
  `exec whisper-server --model "$WHISPER_MODEL_PATH" --host "${WHISPER_HOST:-127.0.0.1}" --port "${WHISPER_PORT:-8080}" --convert`;
  on failure, echo `whisper-model: sidecar not started` to stderr. Using the call as an `if`
  condition is what keeps `set -e` from killing the boot (D-05). `exec` inside the subshell keeps the
  process tree flat.
- Keep `exec bun index.ts` as the last line, unchanged and unconditional — the proxy must reach PID 1
  immediately (D-04).
- Comment the *why* at each non-obvious point, citing the decision IDs: D-04 on the background
  subshell, D-05 on the non-fatal `if`, D-06 on the atomic rename inside `ensure-model.sh`.
