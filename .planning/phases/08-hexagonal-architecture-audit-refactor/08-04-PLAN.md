Output: `composition/container.ts`, two outbound chat-provider factories, a `loadConfig()`-based `config.ts`, zero shims, relocated tests, and updated `CLAUDE.md` / `ARCHITECTURE.md`.

**Provider adapter behaviour that must move verbatim into the outbound factories:**
- Cerebras (`services/cerebras.ts`): the `X-Cerebras-Version-Patch: config.cerebrasVersionPatch` header on both calls; `maxRetries: 0`; the `ChatCompletionCreateParamsNonStreaming` / `Streaming` casts; `withResponse()` for the non-streaming call; field-by-field result construction (never spread); the throw `Cerebras provider is not configured.` when the key is absent.
- Groq (`services/groq.ts`): `maxRetries: 0`; **`temperature === 0 ? 1e-8 : (temperature ?? undefined)` on both the complete and stream calls** (WR-03 — Groq rejects `temperature: 0`); field-by-field result construction; the throw `Groq provider is not configured.` when the key is absent.
- Both: `headers: toHeaderRecord(response.headers) ?? {}` from plan 02, and the streaming generator's conditional delta construction (`role` only when defined, `content` only when the key is present).

**Config contract that must not change:** every current key on `config`, the `requiredPositiveInt` throw message `Config: ${name}="${raw}" must be a positive finite number (got ${value})`, the `PROVIDER_ORDER` validation and its two throw messages, the `MODEL_REGISTRY_JSON` default literal, and the `optional()` → `null` behaviour for absent secrets (missing secrets must NOT crash startup — that is a recorded project decision surfaced via `/ready`).

## Trust Boundaries

| Boundary | Description |

| environment → process | `loadConfig()` becomes the single ingress for `process.env`. Every secret (`PERSONAL_PROXY_API_KEY`, `CEREBRAS_API_KEY`, `GROQ_API_KEY`) enters here and is passed onward by reference through the container. |
