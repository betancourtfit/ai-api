<objective>
Close UAT-04-05 gap: when a client sends Content-Length: 1 with a body larger than 1 MiB, Bun's `request.text()` honors the declared header and delivers only 1 byte. The byte-length gate at line 215 receives a 1-byte string (well under 1 MiB), passes silently, and JSON.parse then fails on the truncated string — producing 400 instead of 413.

Purpose: Fix the body-reading path so actual wire bytes are counted regardless of what Content-Length claims. The security property (request rejected) already holds; this corrects the status code from 400 to 413.

Output: Updated body-reading block in index.ts using a ReadableStream loop with a running byte counter; updated TEST-15 in the integration suite pinned to exactly 413.
</objective>
